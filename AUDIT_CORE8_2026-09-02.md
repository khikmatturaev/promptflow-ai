## Baseline findings and targeted fixes

### 1. Generated React projects were not fully build-safe
The generated React manifest did not include React type declarations, while the generated TypeScript configuration compiled the React entrypoint.

CORE 8 fixes:
- adds `@types/react` and `@types/react-dom` to generated React projects
- uses `jsx: react-jsx`
- keeps `vite/client` typing explicit

### 2. Generated Node projects had an invalid build-output contract
The old shared `tsconfig` used `noEmit: true`, while the Node `start` command expected `dist/main.js`.

CORE 8 fixes:
- React/Vite projects remain `noEmit`
- Node projects now compile from `src` into `dist`
- Node module resolution uses `NodeNext`

### 3. Generated execution commands were package-manager inconsistent
The generated project does not ship a lockfile, while the preflight reported pnpm commands.

CORE 8 fixes:
- execution contract now reports npm commands because the WebContainer runner executes npm directly
- the host PromptFlow project continues to use pnpm

### 4. Atomic WebMCP node schema lagged behind architecture node types
`cdn` and `observability` existed in the architecture type system and Agent OS schema but were missing from the atomic add/update schema.

CORE 8 audit fix:
- atomic WebMCP node type validation now includes `cdn` and `observability`

### 5. Derived execution state required explicit invalidation
Execution is now treated as derived from generated artifacts.

CORE 8 state contract:
- architecture mutations invalidate downstream execution state
- new code generation invalidates execution
- self-healed artifacts are committed before the final execution result is stored

## CORE 8 implementation

### Real execution runtime

PromptFlow now integrates `@webcontainer/api` 1.6.x.

Execution runs inside a browser-native Node.js sandbox:

`Mount → npm install → npm test → npm run build → npm run start → server-ready`

The generated project is never evaluated directly by the PromptFlow host page.

### Self-healing

The loop is bounded to a maximum of three attempts by schema, with two attempts used by the UI default.

Deterministic repair rules currently cover:
- missing React runtime
- missing React type declarations
- broken generated test module boundaries

Network failures are diagnosed but never blindly patched.

Every repair records:
- diagnostic category
- evidence
- confidence
- file path
- before/after patch
- verification state

### Runtime verification

After a successful build, PromptFlow starts the generated project in the sandbox and waits for the WebContainer `server-ready` event.

The execution result can expose a live sandbox preview URL.

### WebMCP

Added:
- `run_project_execution_loop`
- `diagnose_execution_failure`

Current surface:
- **39 WebMCP tools**
- **27 Agent OS tools**
- **12 atomic tools**

## Security boundary

The execution design intentionally avoids:
- `eval`
- `new Function`
- direct execution in the PromptFlow host page
- arbitrary host filesystem access
- automatic secrets injection
- automatic network-error remediation

The WebContainer runtime is isolated from the host page and is used specifically as the execution boundary.

WebContainer requires cross-origin isolation. The project now declares:
- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Embedder-Policy: require-corp`
- existing WebMCP `Permissions-Policy: tools=(self)`
- existing `Origin-Agent-Cluster: ?1`

These headers are configured for Vite server/preview and Vercel deployment.

## Compatibility boundary

CORE 8 real execution currently covers:
- React + Vite
- Node.js / TypeScript service projects

Python projects remain static-preflight only because the current browser runtime is a Node.js WebContainer.

1. Generate Project
2. Execute

4. Verify tests
5. Verify production build
6. Verify runtime/server-ready
7. Open sandbox preview
