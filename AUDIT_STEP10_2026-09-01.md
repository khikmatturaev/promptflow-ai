# PromptFlow.ai — Step 10 Audit & Hardening

Date: 2026-09-01

## Scope

Performance, reliability, WebMCP agent ergonomics, audit correctness, scale edge cases, input hardening, demo telemetry, and metadata/documentation. Existing Step 1–9 architecture was preserved; no foundation rewrite was performed.

## Changes

### 1. React Flow update batching

- Node and edge change events are batched into a single `requestAnimationFrame` update.
- Dragging/selection no longer causes a Zustand write for every high-frequency event.
- Audit invalidation is semantic: position, selection, and dimensions changes do not invalidate an architecture audit.

### 2. Viewport performance

- Removed per-node `fitView()` execution during agent builds.
- Initial fit occurs once when the first node appears.
- Explicit auto-layout continues to refocus the complete graph.
- Layout animation is only triggered when the layout revision actually changes.

### 3. Atomic agent transforms

- `transform_architecture` is explicitly described as the preferred tool for multi-step changes.
- Individual mutation tools now instruct agents to prefer the batch transform for multi-step work.
- Transform operations are still capped at 50 and fully validated before mutation.
- Transform no longer performs a needless auto-layout for update-only operations.
- Scale/fix only trigger layout when they actually have operations to apply.

### 4. Scale reliability

Fixed the previously identified gateway edge case where a compute node without a gateway could produce a connection to a non-existent `api-gateway` when no frontend existed.

Scaling is now idempotent for partially completed architectures:

- gateway is added only for the existing frontend + compute pattern;
- existing gateway is reused;
- missing cache connection is repaired;
- queue and worker are ensured independently;
- missing queue/worker combinations are completed;
- read-replica creation remains guarded and idempotent.

### 5. Audit correctness

Disconnected architecture detection now finds actual weakly connected graph components instead of only finding nodes with zero degree.

This catches cases such as:

```text
Frontend → API → Database

Queue → Worker
```

where every node has an edge but the architecture still contains two disconnected groups.

### 6. Agent Demo correctness

- Tool count monitoring now uses WebMCP `toolchange` events instead of a permanent 1.5-second polling loop.
- A short retry is used only while `document.modelContext` is not yet available.
- Pipeline detection only considers completed tool calls.
- Fix detection recognizes both `fix_architecture` and real mutation tools performed after an audit.
- Verification recognizes a second audit or a successful `fix_architecture` result containing an audit score.
- Demo pipeline now has six explicit stages: Discover → Inspect → Build → Audit → Fix → Verify.
- Activity clearing is labeled `New run / Clear` to make session boundaries explicit.

### 7. WebMCP input hardening

Added bounded input validation:

- node/connection IDs: 120 chars;
- labels: 160 chars;
- descriptions: 800 chars;
- reasons: 600 chars;
- generated code: 50,000 chars;
- transform/fix operation arrays: max 50.

Required identifiers and descriptions are now non-empty.

Tool execution also rejects already-aborted WebMCP signals before starting activity tracking.

### 8. WebMCP registration reliability

Partial registration failures now abort the registration controller before propagating the error, preventing a partially registered tool set from being left active.

### 9. Metadata/documentation

- Replaced the default Vite README with current PromptFlow architecture and WebMCP documentation.
- Updated page title and description for the real product identity.
- Documented production hosting requirement for `Origin-Agent-Cluster` and `Permissions-Policy` headers.

## Final assessment

Step 10 hardening is complete at source level. The architecture remains compatible with the working 12-tool WebMCP integration and the verified ChatGPT desktop real-agent flow.

The main performance win is reducing React Flow/Zustand update frequency and eliminating per-node viewport animations. The main agent-latency win is steering multi-step agents toward the existing atomic `transform_architecture` batch tool rather than adding another redundant architecture mutation API.
