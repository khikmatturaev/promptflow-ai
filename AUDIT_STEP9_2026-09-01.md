## Important real-agent requirement

ChatGPT's current WebMCP site-tool flow is provided through the ChatGPT desktop app's built-in browser. The app must have access to site tools, the PromptFlow page must be the active page, and the account/model must support site tools. The user should not expect ordinary `chatgpt.com` Chrome browsing to automatically act as the WebMCP agent.

For the hackathon demo, the strongest final flow is:

User → ChatGPT desktop built-in browser → PromptFlow page → WebMCP tool discovery → tool calls → live canvas → audit → fix.

## Step 9 acceptance criteria

Step 9 is accepted when:
1. Agent Demo panel shows 12 exposed tools.
2. ChatGPT discovers PromptFlow site tools in its built-in browser.
3. The e-commerce prompt causes real tool calls.
4. PromptFlow canvas changes while ChatGPT works.
5. The Live agent activity feed shows the actual tool names and completion states.
6. Audit and fix calls are visible.
7. The final architecture remains deterministic and inspectable.

No completed Step 1–8 foundation was recreated.
