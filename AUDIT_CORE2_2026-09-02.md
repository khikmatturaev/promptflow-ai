# PromptFlow.ai — CORE 2 WebMCP Agent OS Audit

Date: 2026-09-02

## Scope

The complete uploaded project was reviewed before CORE 2 changes, including application shell, React Flow canvas, Zustand state, CORE 1 intent compiler, architecture audit/intelligence, WebMCP type declarations/registry, Agent panel, Vite WebMCP headers, package metadata, and current documentation.

## Key pre-CORE-2 finding

CORE 1 successfully made the local demo dynamic, but its browser-only intent compiler remained intentionally deterministic. Therefore it could not honestly guarantee deep semantic architecture generation for arbitrary product briefs. The existing 12 WebMCP tools allowed a real ChatGPT agent to overcome that limitation, but complete architectures could still require many low-level tool round-trips.

This was the principal product gap addressed by CORE 2.

## CORE 2 architecture

CORE 2 introduces a high-level WebMCP Agent OS above the existing atomic tools.

### New high-level tools

- `architect_system`
- `analyze_architecture`
- `recommend_architecture`
- `simulate_architecture_scale`
- `apply_architecture_recommendations`
- `explain_architecture`
- `generate_implementation_plan`

Total exposed tools after CORE 2: **19** (7 Agent OS + 12 atomic).

## Arbitrary brief path

`architect_system` supports two execution paths:

1. **Agent semantic plan** — ChatGPT interprets an arbitrary user brief and supplies typed components + directed relationships in a single structured WebMCP call.
2. **Intent compiler fallback** — when the agent supplies only a request, PromptFlow reuses CORE 1's deterministic browser-side planner.

Before a destructive replacement, the complete operation list is validated against an empty graph. PromptFlow only clears the live canvas after validation succeeds. This avoids losing a current architecture because of a malformed agent plan.

After the baseline plan is applied, PromptFlow can automatically:

- add deterministic scale patterns for meaningful targets,
- run structural audit,
- repair deterministic fixable findings,
- auto-layout,
- run final verification audit,
- return node/connection counts and final score to the agent.

## Non-destructive reasoning

`simulate_architecture_scale` projects scale operations against cloned graph state. It returns current/projected metrics and audits without mutating Zustand or the visible canvas.

`analyze_architecture`, `recommend_architecture`, `explain_architecture`, and `generate_implementation_plan` are read-only WebMCP tools.

## Performance / reliability decisions

- No new runtime dependency.
- No network request added.
- No polling added to architecture execution.
- Complete system builds can happen in one high-level agent call rather than many atomic calls.
- Custom plan limits: 40 components / 80 connections.
- Existing transform limit remains 50 atomic operations per low-level transform call.
- Existing rAF React Flow interaction batching remains untouched.
- Existing registry singleton, duplicate registration handling, AbortController lifecycle, HMR cleanup, and execution telemetry remain intact.

## Additional audit corrections

- CORE 1's scale parser previously allowed an unrelated bare number in a brief to become the inferred user scale because the scale unit/user noun was optional. CORE 2 tightens this: a number is treated as scale only when it has a recognized scale suffix (`k`, `million`, `billion`, etc.) or an explicit traffic/user noun.
- The agent telemetry store's new-call status literal could widen to `string` under strict standalone type checking. It is now explicitly preserved as the `"running"` literal, keeping `AgentToolCallStatus` exact.
- The generic scale engine previously hard-coded a PostgreSQL read replica even when the primary database was MongoDB/MySQL/custom. Replica/secondary naming now follows the selected primary database, and gateway insertion is now gated to meaningful scale targets (100k+).

## Agent UX

The Agent panel now represents the high-level Agent OS pipeline:

```text
Discover → Architect → Analyze → Recommend → Simulate → Apply → Explain
```

It reports both total WebMCP tools and Agent OS availability (`7/7 OS`). The demo prompt intentionally uses a media/social/realtime scenario so judges can see semantic agent planning rather than a fixed commerce preset.

## Static QA performed in this environment

- New/modified TypeScript/TSX parsed with the available TypeScript compiler API.
