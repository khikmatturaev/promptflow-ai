## 4. CORE 5 objective

Move PromptFlow from:

`Architecture → Review → Simulation`

to:

`Architecture → Implementation Contract → Project Blueprint → Delivery Plan`

CORE 5 intentionally does not claim to generate production source code. It generates deterministic implementation-planning metadata that an AI agent can use to produce or request real code safely.

## 5. CORE 5 implementation

### New implementation type model

`src/types/implementation.ts`

Adds typed contracts for:

- implementation layers
- implementation maturity
- component implementation maps
- implementation contracts
- delivery phases
- implementation risks
- environment variables / secrets
- test strategy
- complete architecture implementation blueprint

### Implementation Intelligence engine

`src/lib/implementationIntelligence.ts`

Provides:

- stack detection from the live architecture
- component-to-file mapping
- dependency mapping
- interface mapping
- HTTP/event/data/external contract inference
- environment variable and secret requirements
- project structure
- ordered implementation phases
- exit criteria
- implementation risks
- unit/integration/contract/resilience test targets
- readiness scoring
- prioritized first files
- Architecture DNA fingerprint linkage

All analysis is derived from the live Zustand graph and is deterministic.

### WebMCP Agent OS

The Agent OS now exposes 18 high-level tools plus 12 atomic tools = **30 WebMCP tools total**.

New tools:

- `assess_implementation_readiness`
- `generate_project_blueprint`
- `generate_implementation_contracts`

The existing `generate_implementation_plan` tool now returns the richer CORE 5 blueprint rather than the earlier minimal phase-only metadata.

All CORE 5 tools are read-only. They cannot silently mutate the architecture or overwrite code artifacts.

### Canvas / UX

Added `Implementation Intelligence` panel and `Build plan` canvas action.

The panel exposes:

- readiness score
- maturity
- detected stack
- code-ready ratio
- delivery phases
- prioritized first files
- environment contract
- test strategy counts
- implementation risks

Panel visibility is coordinated with the Intelligence and Digital Twin panels to avoid stacked lower-corner overlays.

### State integrity

The implementation blueprint is stored in Zustand as a derived artifact.

Architecture mutations invalidate it together with structural audit, intelligence, and Digital Twin state. This prevents stale implementation plans from being presented after the graph changes.

## 6. Safety / integrity rules

- No source-code overwrite is performed by CORE 5.
- No canvas mutation is performed by CORE 5 tools.
- Existing `generate_node_boilerplate` remains the explicit code-artifact mutation primitive.
- Architecture relationships are mapped into explicit contracts instead of inferred runtime behavior being presented as fact.
- Suggested paths are clearly labelled as planning recommendations.
- Environment values distinguish required/optional and secret/non-secret metadata.
- External integrations receive timeout/retry/fallback contract notes.
- Queue/worker boundaries receive idempotency/retry/dead-letter notes.
- Database boundaries receive migration/restore test targets.
