### Version model

Each checkpoint stores:

- version number and stable id
- release name/message
- timestamp
- deterministic architecture fingerprint
- full node snapshot
- full edge snapshot
- node/connection counts
- audit score at checkpoint time
- Architecture DNA fingerprint

History is bounded to the latest 50 versions.

### Fingerprint

The fingerprint is deterministic and based on normalized component identity/type/label/description/boilerplate plus dependency topology. Ordering does not affect the fingerprint.

Canvas coordinates are intentionally excluded because moving a node is a presentation change, not a runtime architecture change.

### Diff engine

The diff engine detects:

- added components
- removed components
- changed component metadata/type
- moved components
- added dependencies
- removed dependencies

Changes are classified as:

- breaking
- significant
- non-breaking

Risk is deterministic and bounded to 0–100.

### Migration intelligence

Migration planning converts a diff into a controlled rollout sequence:

1. database compatibility
2. data backfill and verification
3. API/event contract compatibility
4. infrastructure provisioning
5. controlled application rollout
6. rollback readiness

It explicitly reports:

- migration risk
- risk score
- data migration requirement
- API compatibility requirement
- downtime risk signal
- preflight checks
- rollback plan

This is architecture planning intelligence, not a production deployment guarantee.
