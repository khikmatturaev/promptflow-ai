- package manifest generation

- architecture/contract documentation

Existing node boilerplate is reused when available; otherwise deterministic scaffolds are produced.

### Execution boundary

The product deliberately does **not** execute arbitrary generated code inside the PromptFlow host page.

`validateGeneratedProject` and `run_project_execution_preflight` provide:

- artifact integrity checks
- manifest checks
- source/entrypoint checks
- test-surface checks
- build readiness
- run readiness
- commands required to run the generated project
- explicit remaining engineering review

This is a browser-safe execution intelligence layer, not a sandbox escape or fake execution claim.

## Environment limitation

The uploaded project does not contain `node_modules`. The available environment also does not have the project's Vite type package installed. Therefore a truthful full `pnpm build` / `pnpm lint` result cannot be claimed here.

Authoritative final gate on the developer machine:

```bash
pnpm install
pnpm build
pnpm lint
```

## Design decision

CORE 6 intentionally stops at a **real, inspectable project scaffold + execution preflight** inside the browser.

It does not pretend that a browser-side deterministic generator has produced production-complete business logic, nor does it execute arbitrary generated source in the host page.

The next logical layer, if desired, is an explicit artifact export/workspace workflow and then deeper implementation/code intelligence—not a rewrite of the existing architecture foundation.
